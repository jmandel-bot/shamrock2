# Shamrock: frontloaded decisions

Experiment: test the "Rust→wasm, no framework, agent hill-climbs a custom harness"
workflow on a small P2P multiplayer board game (a So Clover!-style clover board).

| # | Unknown | Decision | Why |
|---|---------|----------|-----|
| 1 | Who owns logic? | **Rust (`core/`) owns everything**: state, sync/merge, geometry, hit-testing, input handling, rendering. JS is a dumb platform shim. | That's the thesis being tested. |
| 2 | Rust↔JS bridge | **Raw `extern "C"` exports, no wasm-bindgen.** Shared linear memory: Rust writes a draw-command buffer, an outbox, and reads an inbox. | Fewest layers. One less toolchain. |
| 3 | Rendering | **Canvas2D command buffer** (xform / rrect / circle / text) interpreted by ~60 lines of JS. Not WebGPU. | The game is 5 cards and text. WebGPU text rendering would be most of the work and buy nothing here. |
| 4 | P2P transport | **WebRTC data channels via Trystero.** Default signaling is public Nostr relays (no server of our own). `?signal=ws://…` swaps in a self-hosted relay (used by the harness). `?net=local` = BroadcastChannel (same-browser tabs). | Trystero is the only non-Rust code with real logic, and it is vendored as a single bundled file. |
| 5a | Rounds | Every per-round op carries its round (seed + stamp). Any op from a newer round resets a replica, and ops from older rounds are dropped. Within a round: LWW registers per writer / card / check, and a max-merged "current clover" counter. | Out-of-order delivery across rounds can't corrupt state. |
| 5 | Consistency model | **Per-register last-writer-wins with Lamport stamps (clock, peerId).** Registers: deal, 5 cards, 4 clues, saved answer. Full-state exchange on peer join. A new deal makes all older registers invisible (epoch filtering), so state converges without coordination. | No host. Merge is commutative, associative and idempotent, so it's provable by property tests. |
| 6 | Board rotation | **Each player has their own view rotation (local, quarter turns, animated).** Card placement is shared. Cards on the board are stored in *board coordinates* (slot index + rotation relative to the board), so they turn with your view. Cards off the board are stored in *world coordinates* and don't move. | This is the user's requirement, and keeping two coordinate frames makes it fall out naturally. |
| 7 | Slot conflicts | Two cards claiming the same slot: the newer stamp wins, and the loser is shown at a fixed "bumped" spot. A local drop onto an occupied slot **swaps** (the occupant goes to where the dragged card came from). | Deterministic, so every peer shows the same thing. |
| 8 | Game flow | Real So Clover! flow. Everyone writes at once, each on a private clover (4 locked cards, random rotations, derived from round seed + player id, so nothing is sent until submit). Guessing starts automatically when every *connected* player has submitted (presence = 2 s heartbeats, 7 s timeout), with a manual "start without them" escape hatch. Clovers are guessed in submit order, 2 checks each, 6 points for a perfect first try, otherwise 1 per correct card. | Matches the board game and keeps presses minimal. |
| 8a | Fewest presses | Enter on a leaf opens the next empty one and turns the board to face it. A single primary button changes with the phase. Turning the board needs no button (tap ⟳ hub, tap the board, or drag). Each clover starts upright. | User asked for streamlined presses; the harness gates ≤ 6 presses per writer. |
| 10 | Identity | **A seat is a name** (`seat_id = hash(lowercase name)`); devices only break Lamport ties and send presence. Joining under an existing name takes that seat over. Watching = no seat. | Flexible sharing and device switching; it's a low-stakes game. |
| 11 | Game vs round | Ops carry (game, round). New game → wipe everything, re-seat whoever is present. New round → keep seats and the score ledger. | Players come and go over many rounds. |
| 12 | Guessing board | Board ≈ 4× card size; **free placement** (`Float` in board units) with soft snap (34 units) and claim radius (80) for checks; most-recently-moved on top. | Guessers use tentative, half-placed cards as shared thinking space. |
| 13 | Layout | No fixed world: the board fills the screen; tray beside/below it with coordinates normalised to the tray, so each screen lays it out its own way. | Phones need big cards; desktops have spare width. |
| 14 | Animation | Each card's displayed pose eases toward its true pose in its own frame (board or tray), so board spins and card turns both animate without lag. | Jumps were disorienting. |
| 15 | Card size | Per-device zoom (0.8× to 1.53×; at the top end, neighbouring spots touch), display only. | Readable on phones without shrinking the board. |
| 16 | Presence & auto-start | Presence = live connection (link id per peer; dropped on leave), not a timer. Auto-start needs **every seated player** ready; absent players are skipped explicitly. | A device's view of the mesh is partial; any rule based on "who I can see" starts early on some device. |
| 17 | Round roster | Start fixes the round's players (seated + present at that moment), shown on the button. Auto-proceed = all of them submitted, regardless of presence; manual "Proceed with k of n" overrides. | Explicit, deterministic, and a dropped player can't stall or skip silently. |
| 18 | Edits after submit | Submissions are immutable versions keyed (writer, stamp); the guessed clues are the latest version stamped before `Start`. | Lets people keep editing after submitting, while edits racing Proceed converge. |
| 19 | Deck | A 220-card deck (four words per card), dealt as whole cards: `MAX_CARDS` per dealt-in player, from a per-game draw-down deck (reshuffled per pass). | Real game content; no repeats across rounds. |
| 20 | Brand | Own identity: lowercase serif wordmark; mark = four rounded cards set as a clover, one gold (the decoy); felt / paper / gold palette; Fraunces (clues, wordmark) + Figtree (UI, card words); clover-shaped board. Contrast and minimum text size are gated. | Understated, readable, on-brand. |
| 21 | Leaf taps | A tap anywhere on a leaf edits it (when writing) and never turns the board; the editor opens upright on screen. Board turns only via the centre / ⟳ / drag. | Turning on tap was disorienting and lost the editor. |
| 22 | Card size vs words | Cards grew 150 → 210 units at the same word size and board size, so words stay as big on screen while long ones fit. Edge words sit 86 units from centre, giving each a 146-unit budget that can't collide at corners. | Never shrink the text; measured: longest deck word is 141. |
| 23 | No scoring | Guess boots wrong cards (shake, no message), keeps right ones, unlimited tries; solved = all four right. Ledger code stays for wire compatibility but nothing writes it. | Cooperative play; numbers got in the way. |
| 24 | Sharing boards | A link carries chosen clovers as text (the same format as screenshot imports); every device opening it loads the same boards, so a fresh table can play them. | Shareable without any server; works for single boards or sets. |
| 25 | Share links are solo | A share link never connects or asks for a name: it loads the boards and starts guessing locally. Scrambling and unscrambling live in Rust (`scramble`/`unscramble` in `model.rs`); JS only deflates and encrypts the text. | Replaying an old game isn't a social activity tied to a room. Board layout logic belongs with the board model; JS keeps only browser APIs (CompressionStream, WebCrypto). |
| 26 | Room for loose cards | The tray is sized from the current clover's card count (3 per line at this device's card size) and the board shrinks only to fit that; the header bar is gone (menu + player dots float in the board's empty corner). | Cards started out overlapping; 6-card clovers keep full-size cards, 8-card ones get a smaller board rather than overlap. |
| 27 | One-strip dock | Status is one ellipsised line; how-to text moved to once-per-device tips (also in the menu); card size and full screen live in the ⋯ menu; Proceed shows only for players who have submitted (or sit this round out). Only the tray takes a card off the board: a drop anywhere else stays on the board, clamped to its edge. | Screen height goes to the board and tray. Dropping above the board used to send the card to the tray at the bottom. |
| 28 | Pinch zoom | **In-app, on the board only.** A camera (scale + pan, 1–4×) lives in the JS shell: drawing goes through it and pointer coordinates come back through its inverse, so Rust is unaware. Two fingers / ctrl+wheel zoom about the fingers; a second finger cancels the first's gesture in Rust (`pointer_cancel`); 1× resets. Page pinch is off (`touch-action: pan-x pan-y`, Safari gesture events). | Browser page zoom stranded people: once the board filled the screen, one finger plays rather than scrolls and there is no API to unzoom. A camera keeps the dock reachable. |
| 29 | Themes | Light (sage table, white cards) and dark (charcoal, muted leaves, dimmed cards); follows `prefers-color-scheme`, overridable in the menu. Rust holds a `Palette` per theme (`set_theme`); CSS swaps tokens on `data-theme`, set before first paint. | The single dark-green look read as a poor dark mode and ignored the device setting. |
| 30 | Discovery | Six large Nostr relays instead of Trystero's 5 hashed from the app id (obscure hobby relays); when connected to nobody, rejoin the room after 12 s (backing off to 30 s) and on returning to the foreground; the status line says so. | Players didn't see each other until reloading a few times. Couldn't reproduce here (no relay access from CI); these target dead relays and mobile background-tab socket loss. |
| 31 | Home and game log | No `#room` → a home page (new table, my tables, past games) instead of a random room. Finished rounds go to localStorage (cap 60) as answer-order text from Rust (`review`), reviewed as HTML mini clovers, replayable through the share-link path. | Easy to get back to tables and look back at games; nothing needs a server. |
| 32 | Gutters | The layout fits the board to just past the clue text (`FIT_EXTENT` = 410) rather than the leaf lobe tips (432), so only decorative tips touch the screen edge; screen margin 8 → 3 px, tray inset 4 → 2, tray gap 6 → 4, slimmer dock padding (44 px touch targets kept). | On phones width limits everything; cards went from 114 to 123 px on a 390-wide screen. |
| 33 | Clover order | The guessed clover's index is last-writer-wins (by stamp), not grow-only: anyone jumps to any clover; Next goes to the next unsolved (wrapping); End when all are solved. | Tables want to choose order and come back to hard ones. |
| 34 | Players and menu | Menu button in the bottom strip, an Invite button there when it matters, players named in the menu; no colour dots. | Status text pointing at a corner menu was clumsy; dots were a poor stand-in for people. |
| 35 | Card word size | **35** board units (from 26): the largest size at which at most 10 of the deck's 220 cards have centred words colliding at full size (10; 36 has 15). Collision depth counts only the letters near each corner: the shell measures every letter's position and descent, and at each end of a word only letters in the corner zone (where a neighbour's letters could be) set its depth there (a mid-word 'q' no longer counts at the corners). Layout is solved exactly per card: at each corner one word must yield, linear in the size fractions; for each of the 16 choices, minimise squared shrinkage via KKT; keep the best, ties to the bigger smallest word. Smallest word 82%; most shrinks are 95–99%. | Sizing for the longest word wasted the card; whole-word depth flagged corners where no deep letter was near (magician/mosquito). |
| 36 | Naming tables and players | The table name is the link and the only key, so suggestions are adjective-animal-place, e.g. merry-otter-cove (short common words, over a million combinations, no digits); a typed name is used as typed, made link-safe (no hidden tag; this is friends-scale). Your name is remembered across tables and pre-filled everywhere; a remembered name joins on arrival, a new table link is one tap. | Starting or joining should be one step, with names editable inline. |
| 37 | Round recap | When the last clover is solved, a sheet opens on every screen with all of the round's clovers in a row, scrolled from one to the next (no expanding rows): clues with the two words each linked, answer cards showing outward words, decoys, guesses taken, round totals. The status line reopens it. Past games use the same clover view. | The round ended on an empty board, so nobody saw what the clues had meant; agents and people both asked for it. |
| 38 | Tools for AI assistants | The page offers its moves as WebMCP tools when the browser supports it (feature-detected; no dependencies), acting through the same Rust input path as touch and seeing only this player's view; answers only after the round. The play-test driver calls the same tools. | Opens the game to browser assistants (a seat, a nudge, voice play) at the cost of one small module, and tests exercise exactly that surface. |
| 39 | Flick to turn | A released board spin coasts 0.18 s at its last 120 ms of speed, then settles on the nearest quarter. | Short flicks were ignored: only a drag past 45° turned the board. |
| 40 | One table, ranked rounds | No "game" container that replaces another wholesale. Seats belong to the table and only merge (a device that's here keeps its seat active); everything else belongs to a round, ranked by (epoch, rounds dealt, players dealt in, age); New game is the next epoch's lobby and marks absent players inactive. The unused score ledger is gone. | Wholesale replacement erased tables when devices that started apart met; the patches for it (ensure-game, generations, re-seating) all go. |
| 41 | Unreliable networks | A simulator plays whole games under link loss, partitions, reloads and closes. Besides #40: tables are saved per device (6 h) and restored on load; presence pings carry a table hash and drifted devices resync (at most every 5 s); holds ride on live pointer messages rather than shared state; *Deal again* when everyone dealt in has gone. | Bugs found by the simulator: table wipes, lost tables, permanent divergence, ghost holds, a dead end. |
| 42 | One round-change path | Round headers carry their lineage (table, parent, dealer). Any change of round, local or remote, goes through one path: the old round is kept in Past games (upserted by key, marked unfinished if it was), kept in memory for late edits, and, unless this device did it, explained once by what it was (next, missed, crossed, new game, other table) in a notice and under What happened. Another table's group can Move to a fresh room (a shared move record; its devices are offered one tap to follow). Hello and saves carry a protocol version. See docs/sync-model.html. | Replaces the special-cased set-aside event: one rule for every cause, tested by the simulator (exactly one notice per change; every round kept) and browser scenarios. |
| 9 | What "good" means | `harness/` produces a scorecard: correctness gates (convergence, rotation invariants, swap, late join, clue sync, conflict) plus numbers (sync latency, frame cost, wasm size, bytes per drag update, legibility in CSS px at desktop and phone sizes). | The thing the agent climbs. |
